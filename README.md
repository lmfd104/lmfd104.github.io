# lmfd104.github.io

The product site for the apps, served by GitHub Pages. Everything here is static — Pages runs no
build step, so the generated output is committed.

## What is generated, and by what

Do not hand-edit the generated pages; the next build overwrites them. The generators live in the
`Claudebuilder` workspace repo.

| Path | Generated by | Notes |
|---|---|---|
| `index.html`, `<app>/`, `rules/<app>/`, `rules/index.html`, `play/index.html` | `tools/build_site.py` | Page content and app copy live in `APPS` in that file |
| `assets/img/**` | `tools/build_site_assets.py` | Store artwork, downscaled to WebP |
| `rules/data/**` | `tools/build_rules_data.py` | Extracted from what Starfarer's Ledger and Hero's Ledger actually ship |
| `play/theguild/**` | `GuildHall`: `npm run build && node tools/build-web-demo.mjs <dest>` | The free browser demo, with paid cosmetics stripped |

Hand-written and safe to edit directly: `assets/site.css`, `rules/rules.css`, `rules/rules.js`, the
`*-privacy.html` / `*-support.html` pages, `discord/`, and this README.

## Rebuilding

```bash
python tools/build_rules_data.py     # refresh the rules catalogue from the app repos
python tools/build_site_assets.py    # refresh screenshots and icons
python tools/build_site.py           # regenerate the pages
python tools/check_site_links.py     # fail on any broken local reference
```

## Things that will bite you

- **Store links are only listed for apps whose Play production track is live.** An alpha or
  internal build is not publicly reachable, and linking one gives every visitor a dead store page.
  Check with `node tools/play-api.mjs tracks <pkg>` before adding one.
- **The Guild demo must be rebuilt through `build-web-demo.mjs`, never copied from `www/`.** `www/`
  is the Android bundle and contains the paid Painted Legends portraits and Wardrobe themes, which
  would then sit at guessable public URLs.
- **`index.html` carries the TikTok OAuth `?code=` handler.** It is invisible on a normal visit but
  the upload pipeline depends on it. It lives in `build_site.py`; keep it when editing.
- CSS and JS are referenced with a content-hash query (`?v=…`) so a redeploy does not leave
  returning visitors on a cached stylesheet.
